# HIVE Security Policy

## Reporting a Vulnerability

Please report suspected security vulnerabilities privately. Do not open a public GitHub issue, discussion, or pull request containing exploit details, credentials, private data, or instructions that would enable abuse.

Use GitHub's **Report a vulnerability** function on the repository's Security tab:

https://github.com/bargeranthony-gif/HIVE/security/advisories/new

If private vulnerability reporting is unavailable, contact the repository owner through a private channel associated with the GitHub account and request a secure method for sharing the report. Do not include secrets or sensitive personal information in an ordinary public issue.

## What to Include

When safe to do so, include:

- A concise description of the affected component and the potential impact.
- The affected commit, branch, release, or version.
- Reproduction steps or a minimal proof of concept that does not access data or systems you do not own or have permission to test.
- Relevant logs, screenshots, or request/response details with credentials, tokens, personal data, and other secrets removed.
- Any suggested mitigation.

## Coordinated Disclosure

Please allow the maintainers a reasonable opportunity to investigate, develop a fix, and coordinate disclosure before publishing vulnerability details. Do not exploit a vulnerability beyond what is necessary to demonstrate it, disrupt services, access another person's data, or perform testing without authorization.

The maintainers will make a good-faith effort to acknowledge and investigate reports. Response and remediation timelines are not guaranteed while the project is under active development.

## Supported Versions

HIVE is currently under active development and does not yet publish a formal supported-release matrix. If you believe you have found a vulnerability, report it against the latest code or release you tested and identify the exact commit or version.

## Scope

Security reports are welcome for vulnerabilities affecting HIVE's source code, installation and update processes, node runtime, authentication and authorization boundaries, data handling, dependency management, and repository automation.

This policy does not grant permission to test systems, infrastructure, accounts, or nodes operated by HIVE contributors or third parties.
